# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MakeCV (makecv.org) is a **zero-build static resume builder**. The application itself — HTML, CSS, JavaScript, all 10 CV templates, and all UI — lives in `index.html` (≈2500 lines). Around it sit 17 static content pages (template gallery, template styles, guides, about, privacy) that are generated by a small stdlib-only Python script (see *Content pages*). There is no package manager, no bundler and no framework.

## Running / Developing

Open `index.html` directly in a browser, or serve it locally:

```bash
npx serve .          # or: python3 -m http.server 8080
```

`python3 -m http.server` only serves content pages with their `.html` extension; `npx wrangler dev` reproduces Cloudflare's routing (extensionless URLs, trailing-slash redirects, the 404 page).

Hosted on Cloudflare Workers (static assets only, `wrangler.jsonc`; the repo root is the asset directory and `.assetsignore` excludes docs/config). Security and cache headers live in `_headers`. **Every push to `main` deploys automatically via Workers Builds** (trigger "Deploy main": no build command, deploy command `npx wrangler deploy`); `npx wrangler deploy` (or `./sw deploy makecv` from the workspace root) still works for a manual deploy. Workers Builds does not run `tools/build_pages.py`: commit the generated pages. `makecv.org` is a Workers custom domain since 2026-10-27; the old Vercel CNAME and `_vercel` TXT records were deleted. `www.makecv.org` → apex is a separate Worker in `www-redirect/` (`npx wrangler deploy -c www-redirect/wrangler.jsonc`).

## Architecture

### Single-file structure (index.html)

| Section | Lines (approx) | Description |
|---|---|---|
| `<head>` | 1–260 | Meta, SEO, JSON-LD, fonts, GA snippet, Tailwind CDN |
| `<style>` | ~262–819 | All CSS — Tailwind via CDN + custom per-template styles |
| `<body>` HTML | ~821–1527 | Header, 3-step wizard UI, How it works, FAQ, Templates & Guides links, testimonials, footer |
| `<script>` | ~1528–2314 | All app logic |
| Cookie / Privacy | end of file | Cookie consent banner, privacy modal (its script waits for DOMContentLoaded: the markup comes after it) |

### External dependencies (CDN only — no npm)
- **Tailwind CSS** — utility classes in the HTML
- **Font Awesome** — icons
- **html2pdf.js** — client-side PDF generation via html2canvas + jsPDF. Not in `<head>`: `loadHtml2pdf()` injects it when step 3 opens and `downloadPDF()` awaits it. The PDF it makes is **image-based** (text not selectable); the ATS PDF (`printATS()` → browser print → Save as PDF) is the text-based one.
- **Google Fonts** — Plus Jakarta Sans (UI) is render-blocking; the template fonts load non-blocking (`media="print" onload`).

### App state

All state lives in a single in-memory `cv` object:

```js
cv = {
  personal: { name, title, email, phone, city, linkedin, website, photo },
  summary: '',
  experience: [],   // max 5
  education: [],    // max 3
  skills: [],       // { name, level: 'Începător'|'Mediu'|'Avansat' }
  languages: [],    // max 4
  projects: [],     // max 3
  certifications: [],// max 4
  selectedTemplate: 'modern'
}
```

No localStorage persistence (except cookie consent in `makecv_cookie_consent`). Refresh clears all data.

### Key functions

- `upd(path, val)` — dot-path state updater, triggers `renderCV()` if on step 3
- `updEntry(type, idx, field, val)` — updates a repeatable list entry
- `renderCV()` — writes `TPLS[cv.selectedTemplate](cv)` into `#cv-preview`
- `goStep(n)` — shows step n, hides others; step 3 triggers renderCV + scale
- `selTpl(name)` — sets `cv.selectedTemplate`, highlights template card
- `applyScale()` — CSS-transforms the preview to fit the viewport
- `downloadPDF()` — async; loads html2pdf if needed, waits for fonts, resets transform to scale(1) before html2pdf capture, then restores
- `printATS()` — copies the preview into `#ats-print-layer` and calls `window.print()`; temporarily sets `document.title` to `Firstname-Lastname-Resume` so Save as PDF suggests that file name. Print CSS forces backgrounds (`print-color-adjust: exact`)
- `/?template=<key>` preselects a template on load (used by the content pages' "Use the … template" buttons); the canonical stays `/`
- `e(s)` — HTML escape helper; **must be used on all user-supplied content rendered into templates**
- `barW(lvl)` — maps Romanian skill levels to progress bar widths (32/62/92%)

### Templates

The `TPLS` object maps 10 template keys to functions `(cv) => htmlString`:

`clasic`, `modern`, `minimalist`, `creativ`, `executive`, `tech`, `bloom`, `neon`, `aurora`, `swiss`

Each template function renders directly from the `cv` state object. Templates contain their own layout CSS under `.tpl-<name>` classes in the `<style>` block.

Template section headings and the UI are in English. **Important**: skill levels are still stored as Romanian strings (`'Mediu'`, `'Avansat'`, `'Începător'`) — `barW()` depends on these exact strings.

Template previews used by the content pages are screenshots in `img/templates/<slug>.jpg` (640×906, slugs: classic, modern, minimalist, creative, executive, tech, bloom, neon, aurora, swiss), taken from the builder with a fictional sample resume ("Jordan Taylor"). Re-shoot them if a template's design changes.

### Ads

**Adsterra only** (there is no AdSense). Slots are `<aside class="ad-slot" data-ad="…">` placeholders in the HTML; the ADS script at the end of `<body>` fills each one when it first comes within 300px of the viewport (IntersectionObserver), so slots in hidden steps or `lg:hidden` variants never request an ad. Keys and zones live in that script's `BANNERS` / constants.

| `data-ad` | Size | Where |
|---|---|---|
| `leaderboard` | 728×90, 320×50 below 768px | Step 1, under the hero |
| `inline` | 468×60, 320×50 below 768px | Step 1, before Languages |
| `native` | /21/ native banner (`#container-<zone>`, one per page) | Step 2, under the template grid |
| `300x250` | 300×250 | Step 3: left panel from 1024px (panel widens to `lg:w-80`), under the preview below 1024px |
| `responsive` | 728×90, 300×250 below 768px | Between How it works and the FAQ |
| `rail-left` / `rail-right` | 160×600 / 160×300 | Fixed beside the active step, only when they fit (`placeRails`, re-run on `goStep` and resize) |

- Iframe banners (/22/) each render in their own `srcdoc` iframe: the invoke script reads the global `atOptions` and uses `document.write`.
- **Social Bar** (/14/) loads 1.5 s after `load`, every page view.
- **Popunder** (/1/, afders.org) loads only after the visitor gets a PDF (`makecv:downloaded`, fired by `downloadPDF()` and `printATS()`), once per session (`sessionStorage.makecv_pu`). It binds a page-wide click handler, so loading it earlier hijacks clicks in the form.
- **Direct link** (arwf.org): the `a[data-ad-link]` "Sponsored" cards in step 3 (`rel="sponsored"`, new tab).
- `@media print` hides `body > *`, so no ad reaches the ATS print.
- `sw.js` is a kill switch for an old third-party push service worker removed on 2026-10-27: browsers that registered it keep re-fetching the file, and this version unregisters itself (dropping the push subscription) and reloads open tabs. It is served `no-cache`. Delete `sw.js` and its `_headers` entry after 2026-11-26.
- The cookie banner and privacy policy (modal) describe Adsterra; `ads.txt` lists no sellers (no AdSense).

### Analytics

Google Analytics 4: inline script at the top of `<head>` (`GA_ID`, empty = no tag; only runs on the `makecv.org` hostname). Consent Mode v2 denies storage by default in the EEA/UK/CH and grants it elsewhere; `acceptCookies()` / `declineCookies()` call `makecvConsent()` to update it, and a stored choice is applied on every load.

### SEO / Structured data

`index.html` head: one JSON-LD `@graph` (`WebSite`, `Organization` with `logo.png`, `WebApplication`), plus `HowTo` and `FAQPage`. The FAQPage text mirrors the visible FAQ section word for word: change both together. No `AggregateRating`/`Review` markup (there are no real reviews).

## Content pages

Every page except the builder is generated: edit `tools/pages/<name>.html` (a JSON meta block in an HTML comment, then the article body), then run

```bash
python3 tools/build_pages.py
```

It writes the page to the served path (`/resume-templates/modern` → `resume-templates/modern.html`; Cloudflare's `drop-trailing-slash` serves it without `.html`), regenerates `sitemap.xml` (home + every non-noindex page, `lastmod` = the fragment's `updated`; bump `HOME_LASTMOD` in the script when the builder's content changes), and fails on duplicate titles/descriptions/H1s or links to unknown pages. Body placeholders: `{{tpl:<slug>}}` / `{{tplfirst:<slug>}}` (template figure), `{{tplcard:<slug>}}`, `{{cta}}`. Shared page CSS is `guide.css`; header/footer, the GA snippet (an exact copy of index.html's) and JSON-LD (BreadcrumbList + Article/CollectionPage/AboutPage + FAQPage from the meta `faq`) live in the script. `tools/` is in `.assetsignore`.
