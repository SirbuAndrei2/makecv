# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MakeCV (makecv.org) is a **zero-build static resume builder**. The application itself — HTML, CSS, JavaScript, all 14 CV templates, and all UI — lives in `index.html` (≈2860 lines). Around it sit 20 static content pages (template gallery, template styles, guides, about, privacy) that are generated by a small stdlib-only Python script (see *Content pages*). There is no package manager, no bundler and no framework.

## Running / Developing

Open `index.html` directly in a browser, or serve it locally:

```bash
npx serve .          # or: python3 -m http.server 8080
```

`python3 -m http.server` only serves content pages with their `.html` extension; `npx wrangler dev` reproduces Cloudflare's routing (extensionless URLs, trailing-slash redirects, the 404 page).

Hosted on Cloudflare Workers (static assets only, `wrangler.jsonc`; the repo root is the asset directory and `.assetsignore` excludes docs/config). Security and cache headers live in `_headers`. **Every push to `main` deploys automatically via Workers Builds** (trigger "Deploy main": no build command, deploy command `npx wrangler deploy`); `npx wrangler deploy` (or `./sw deploy makecv` from the workspace root) still works for a manual deploy. Workers Builds does not run `tools/build_pages.py`: commit the generated pages. `makecv.org` is a Workers custom domain since 2026-10-27; the old Vercel CNAME and `_vercel` TXT records were deleted. `www.makecv.org` → apex is a separate Worker in `www-redirect/` (`npx wrangler deploy -c www-redirect/wrangler.jsonc`).

## Architecture

### Single-file structure (index.html)

| Section | Lines (approx) | Description |
|---|---|---|
| `<head>` | 1–261 | Meta, SEO, JSON-LD, fonts, GA snippet, Tailwind CDN |
| `<style>` | 262–1029 | Design tokens + UI components (262–544), template CSS (545–710, `.cvt` shared rules + the 4 newer templates at the end), ad slots, cookie banner, modal |
| `<body>` HTML | 1031–1690 | Sticky header with stepper, step 1 (hero, form, live preview), step 2 (template picker), step 3 (preview + download), after-builder ad, How it works, FAQ, Templates & Guides links, testimonials, footer |
| `<script>` | 1692–2660 | All app logic, then `TPLS` |
| ADS script | 2662–2793 | Rails markup + the Adsterra mounting script |
| Cookie / Privacy | end of file | Cookie consent banner, privacy modal (its script waits for DOMContentLoaded: the markup comes after it) |

### External dependencies (CDN only — no npm)
- **Tailwind CSS** — utility classes in the HTML
- **Font Awesome** — icons
- **html2pdf.js** — client-side PDF generation via html2canvas + jsPDF. Not in `<head>`: `loadHtml2pdf()` injects it when step 3 opens and `downloadPDF()` awaits it. The PDF it makes is **image-based** (text not selectable); the ATS PDF (`printATS()` → browser print → Save as PDF) is the text-based one.
- **Google Fonts** — Plus Jakarta Sans (UI) is render-blocking; the template fonts (Lora, Source Sans 3, Playfair Display, Inter, DM Sans, Nunito, Space Grotesk, EB Garamond, Source Serif 4) load non-blocking (`media="print" onload`).

### App state

All state lives in a single in-memory `cv` object:

```js
cv = {
  personal: { name, title, email, phone, city, linkedin, website, photo },
  summary: '',
  experience: [],   // max 5
  education: [],    // max 3
  skills: [],       // { name, level: 'Începător'|'Mediu'|'Avansat' }
  languages: [],    // max 4
  projects: [],     // max 3
  certifications: [],// max 4
  selectedTemplate: 'modern'
}
```

No localStorage persistence (except cookie consent in `makecv_cookie_consent`). Refresh clears all data.

### Key functions

- `upd(path, val)` — dot-path state updater; calls `queueRender()`
- `updEntry(type, idx, field, val)` — updates a repeatable list entry; calls `queueRender()`
- `queueRender()` — one debounced (250 ms) re-render: `renderCV()` on step 3, `renderMini()` on step 1
- `renderCV()` — writes `TPLS[cv.selectedTemplate](cv)` into `#cv-preview`, updates the download buttons, the "Fits on 1 page / N pages" badge and the scale
- `renderMini()` — step-1 live preview (`#mini-preview`), only from 1280px; scaled to the column width and viewport height
- `goStep(n)` — shows step n, sets `body[data-step]` (CSS hooks for step-only UI), step 3 triggers renderCV + scale. The ADS script wraps it (rails, social bar)
- `selTpl(name)` — sets `cv.selectedTemplate`, highlights the card, syncs the step-3 `#tpl-switch` select and the "Selected:" labels
- `filterTpl(tag)` — step-2 filter chips (`data-tags` on each card: ats, one, two, photo, color, dark)
- `checkField` / `clearErr` / `setErr` — inline validation for name and email (`RULES`); `missing()` lists what blocks the download and `updateDlBtn()` renders it as "To download, add …" links (`fixField()` jumps to the field)
- `removePhoto()`, `addSkill()` / `addSkillFromInput()` — photo removal, skills via Enter, comma or the Add button
- `moOpts(v)` / `yrOpts(v)` — month/year options with the entry's value preselected (re-rendering a list keeps dates)
- `applyScale()` — CSS-transforms the preview to fit its column
- `keepAdsClearOfBar()` — phones, step 3: slides the fixed download bar away while any ad slot is within its height + 24px
- `downloadPDF()` — async; loads html2pdf if needed, waits for fonts, captures at scale(1) with `.pdf-capture` (caps the page at 1122px so A4 at margin 0 stays one page; solid colours for gradient text html2canvas can't paint). Options: margin 0 (templates carry their own margins), `pagebreak: css` (entries carry `break-inside: avoid`), `enableLinks`
- `printATS()` — copies the preview into `#ats-print-layer`, removes icon-font `<i class="fa-…">` glyphs (they extract as junk text), sets `document.title` to `Firstname-Lastname-Resume` for the Save as PDF name, calls `window.print()`. Print CSS forces backgrounds (`print-color-adjust: exact`) and avoids breaks inside entries
- `/?template=<key>` preselects a template on load (used by the content pages' "Use the … template" buttons); the canonical stays `/`
- `e(s)` — HTML escape helper; **must be used on all user-supplied content rendered into templates**
- `barW(lvl)` — maps Romanian skill levels to progress bar widths (32/62/92%); `dots(s)` derives 1–3 dots from it

| `minimalist` | Minimalist | Best | One column, dates in a left margin, no photo | |

| `swiss` | Swiss | Good | Main + narrow right column, red accents | |

| `bloom` | Bloom | Fair | Pastel, emoji section icons | |

Template conventions (follow them in new templates):
- Root element `<div class="tpl-<name> cvt">`; template CSS is scoped under `.tpl-<name>` (never `#cv-preview`, because the ATS print layer and the live preview reuse the HTML).
- Use the shared helpers: `contactList(p)` (escaped, linked contact items), `photo(p, cls)` (**renders nothing without a photo**; no placeholders), `bullets(text)` (one line = paragraph, several lines or leading -/• = bullet list), `xpDates` / `eduYears` (one date format, "Mar 2022 – Present"), `projLink`, `certLine`, `dots`, `sec(title, body)` (omits empty sections).
- `.cvt .entry` has `break-inside: avoid`; `.e-head` puts title and date on one row.
- Every user value goes through `e()`.

Template section headings and the UI are in English. **Important**: skill levels are still stored as Romanian strings (`'Mediu'`, `'Avansat'`, `'Începător'`) — `barW()` depends on these exact strings. The form shows them as Beginner / Intermediate / Advanced.

Template previews are screenshots in `img/templates/<slug>.jpg` (640×906, used by the content pages) and `img/templates/thumbs/<slug>.jpg` (320×453, step-2 picker, ~14 KB each), slugs: professional, harvard, classic, modern, student, compact, minimalist, executive, swiss, creative, tech, aurora, bloom, neon. They are taken from the builder (step 3, preview at scale 1, header and preview toolbar hidden) with a fictional sample resume ("Jordan Taylor", descriptions as bullet lines), cropped to A4 and resized with PIL. Re-shoot them if a template's design changes.

### Design system

From the ui-ux-pro-max plugin (`search.py "resume builder career tool SaaS free" --design-system`): **Minimalism & Swiss style** for a SaaS tool. Tokens live in `:root` at the top of the `<style>` block in index.html and are mirrored in `guide.css`:

- Colours: navy `#1E3A5F` (brand mark, selected chips, Professional template), action blue `#2563EB` / hover `#1D4ED8` (primary buttons, links, focus ring), success green `#15803D` on `#F0FDF4`, background `#F8FAFC`, text `#0F172A` / `#334155` / `#475569` / `#64748B`, borders `#CBD5E1` / `#E2E8F0`. All text pairs meet WCAG AA.
- Type: Plus Jakarta Sans everywhere in the UI; inputs 16px on phones (no iOS zoom), 14.5px from 768px.
- Components: `.form-card` + `.card-head`, `.lbl`, `.inp` (44px min height, focus ring), `.field-err`, `.btn-blue` / `.btn-ghost` / `.btn-add` / `.btn-del` / `.btn-link` (44px targets), `.step-actions` (sticky bottom action bar), `.chip`, `.f-chip`, `.tpl-card`, `.side-card`, `.preview-bar`.
- Rules: visible labels (no placeholder-only fields), errors next to the field with `aria-invalid` + `aria-describedby`, `:focus-visible` ring on everything, `prefers-reduced-motion` honoured, no emoji as UI icons (Font Awesome), reserved heights for anything that loads late (ads, thumbnails).

### Ads

**Adsterra only** (there is no AdSense). Slots are `<aside class="ad-slot" data-ad="…">` placeholders in the HTML; the ADS script at the end of `<body>` fills each one when it first comes within 300px of the viewport (IntersectionObserver), so slots in hidden steps or `lg:hidden` variants never request an ad. Keys and zones live in that script's `BANNERS` / constants. Each slot reserves its final height in CSS before it mounts (no layout shift) and shows an "Advertisement" label.

Placement rule: ads sit where attention naturally pauses, never between the hero and the first form card, never between the template grid and its buttons, and never next to Next/Download (the sticky action bars rest at least 40px away; on phones the fixed download bar slides away while an ad is near it).

| `data-ad` | Desktop (≥768px) | Mobile (<768px) | Where | Why there |
|---|---|---|---|---|
| `inline` | 468×60 | 320×50 | Step 1, between Skills and "Optional sections" | Natural break after the core sections; far from the Next button |
| `leaderboard` | 728×90 | 300×250 | After the builder (`.after-builder`), steps 1 and 3; hidden on step 2 | End of the form / below the preview; separated from the step's action bar |
| `native` | /21/ native block | same | Step 2, below the Back / Preview bar (40px gap) | After the choice is made, not between the grid and the buttons |
| `300x250` | 300×250 in the step-3 left panel (≥1024px) | — (the after-builder slot serves phones and tablets) | Step 3, under the panel's buttons and tip | Beside the preview, away from the Download buttons in the toolbar |
| `responsive` | 728×90 | 300×250 | Between How it works and the FAQ | Reading content, not the task |
| `rail-left` / `rail-right` | 160×600 / 160×300 | — | Fixed beside the active step's content box (`[data-rail-anchor]`) | Only where both sides have ≥192px free and the viewport is tall enough (`placeRails`, re-run on `goStep` and resize); in practice step 2 from ~1410px wide, step 1 at ~1085–1279px and from ~1565px (the live preview widens it at 1280px), step 3 from ~1620px; the 160×600 also needs a ≥726px-tall viewport |

- Iframe banners (/22/) each render in their own `srcdoc` iframe: the invoke script reads the global `atOptions` and uses `document.write`.
- **Social Bar** (/14/): once per page view, at the first natural pause — leaving step 1 (`goStep(2|3)`) or scrolling to "How it works" (`#hiw`) — and never before `load`. It used to load 1.5 s after load, where its floating unit could cover form fields on phones while people were typing. Trade-off: visitors who leave during step 1 without scrolling never load it.
- **Popunder** (/1/, afders.org) loads only after the visitor gets a PDF (`makecv:downloaded`, fired by `downloadPDF()` and `printATS()`), once per session (`sessionStorage.makecv_pu`). It binds a page-wide click handler, so loading it earlier hijacks clicks in the form.
- **Direct link** (arwf.org): the `a[data-ad-link]` "Sponsored" cards: step-3 left panel from 1024px, under the preview below that (`.step3-only`).
- **Content pages**: one in-content banner (`data-ad="incontent"`, 728×90 / 300×250 below 768px) between the article and the FAQ on template and guide pages, added by `build_pages.py` (`AD_SLOT` / `AD_SCRIPT`, same zone keys and srcdoc approach). None on about, privacy or 404; no social bar or popunder on content pages.
- Trade-offs vs before: no ad above the fold on step 1 (the old leaderboard sat under the hero), and the rails show on fewer screens because the step-1 live preview widens the content from 1280px. In exchange the form, picker and download are never interrupted, and the content pages gained a unit.
- `@media print` hides `body > *`, so no ad reaches the ATS print.
- `sw.js` is a kill switch for an old third-party push service worker removed on 2026-10-27: browsers that registered it keep re-fetching the file, and this version unregisters itself (dropping the push subscription) and reloads open tabs. It is served `no-cache`. Delete `sw.js` and its `_headers` entry after 2026-11-26.
- The cookie banner and privacy policy (modal) describe Adsterra; `ads.txt` lists no sellers (no AdSense).

### Analytics

Google Analytics 4: inline script at the top of `<head>` (`GA_ID`, empty = no tag; only runs on the `makecv.org` hostname). Consent Mode v2 denies storage by default in the EEA/UK/CH and grants it elsewhere; `acceptCookies()` / `declineCookies()` call `makecvConsent()` to update it, and a stored choice is applied on every load.

### SEO / Structured data

`index.html` head: one JSON-LD `@graph` (`WebSite`, `Organization` with `logo.png`, `WebApplication`), plus `HowTo` and `FAQPage`. The FAQPage text mirrors the visible FAQ section word for word: change both together. No `AggregateRating`/`Review` markup (there are no real reviews).

## Content pages

Every page except the builder is generated: edit `tools/pages/<name>.html` (a JSON meta block in an HTML comment, then the article body), then run

```bash
python3 tools/build_pages.py
```

It writes the page to the served path (`/resume-templates/modern` → `resume-templates/modern.html`; Cloudflare's `drop-trailing-slash` serves it without `.html`), regenerates `sitemap.xml` (home + every non-noindex page, `lastmod` = the fragment's `updated`; bump `HOME_LASTMOD` in the script when the builder's content changes), and fails on duplicate titles/descriptions/H1s or links to unknown pages. Body placeholders: `{{tpl:<slug>}}` / `{{tplfirst:<slug>}}` (template figure), `{{tplcard:<slug>}}`, `{{cta}}`. Shared page CSS is `guide.css` (same design tokens as the builder); header/footer, the in-content ad, the GA snippet (an exact copy of index.html's) and JSON-LD (BreadcrumbList + Article/CollectionPage/AboutPage + FAQPage from the meta `faq`) live in the script. `tools/` is in `.assetsignore`.
